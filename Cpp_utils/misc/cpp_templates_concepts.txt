Key Concepts in the Article
The Problem with Traditional Templates (Pre-C++20)
Without constraints, templates accept almost any type, leading to deeply nested, hard-to-read compiler errors when an invalid type (such as a custom struct missing operator overloads) is passed.
Older workarounds like std::enable_if were syntactically heavy and difficult to read.
Introduction to Concepts & requires Clauses
Concepts allow developers to explicitly define and enforce type requirements directly on templates.
Using the requires keyword (or shorthand syntax like template<std::integral T>), you can restrict templates to specific categories of types (e.g., integers, floating points).
Better Error Messages: Instead of long internal template expansions, failures clearly state constraints not satisfied.

Standard Library Concepts
C++20 provides built-in standard concepts in the <concepts> header, such as std::integral, std::floating_point, std::same_as, std::derived_from, and std::copyable.
Defining Custom Concepts (requires Expressions)
Developers can create their own custom concepts using requires expressions to check for specific syntactic requirements.
Capabilities Checked via Requires Expressions:
Expression validity: Ensuring an expression (like a + b or std::cout << value) is valid.
Member function existence: Checking if a container type has specific methods like container.begin().
Return type constraints: Constraining the return type of an expression (e.g., -> std::convertible_to<bool>).
Exception safety: Guaranteeing functions are noexcept.

Summary of Benefits
Readability: Clear, declarative type constraints communicate the design intent of the API instantly.
Maintainability: Replaces complex std::enable_if constructs with clean, readable syntax.
Debugging: Pinpoints incorrect usage early with straightforward compile-time error messages.

C++20 Concepts – New features to make templates safer and easier to understand

##Problems with traditional templates
First, let's look at an example where there are no Concepts.

template<typename T>
T Add(T a, T b)
{
    return a + b;
}

This function appears at first glance to accept any type.
It actually works without any problems if you use integer or floating-point types.

std::cout << Add(3, 5) << '\n';
std::cout << Add(1.5, 2.5) << '\n';

But what happens if we pass a type that doesn't have a + operator?

struct Player
{
};

Add(Player{}, Player{});

##Let's try using Concepts
Concepts allow you to pre-restrict the types that will be accepted.

 #include  <concepts>

template<typename T>
requires std::integral<T>
T Add(T a, T b)
{
    return a + b;
}

std::integral is a standard concept that represents "being an integer type".

## The requires clause is
"This template can only be used with types that meet these conditions."
This is the syntax for writing constraints like this.

for example,
template<typename T>
requires std::floating_point<T>
void Print(T value)
{
    std::cout << value << '\n';
}

This function only accepts floating-point numbers.

Print(3.14);     // OK
Print(1.0f);     // OK
Print(10);       // エラー


##Standard Library Concept
C++20 includes pre-defined constraints for commonly used situations.

Concept Description std::integral integer type std::floating_point floating-point type std::same_as<T, U> same type std::derived_from<T, U> inheritance relationship std::convertible_to<T, U> type convertible std::default_initializable default constructible std::copyable copyable std::movable moveable

By simply using these, you can write many templates in an easy-to-understand way.


##Define your own Concept
The standard library provides many convenient Concepts, but there are times when you want to describe constraints that cannot be expressed using only Concepts.

In such cases, you can define your own Concept.

For example, let's define a concept called "Types that can use the + operator".

template<typename T>
concept Addable = requires(T a, T b)
{
    a + b;
};


##The defined Concept can be used in the same way as a standard Concept.

template<Addable T>
T Add(T a, T b)
{
    return a + b;
}

Now, only types that have the + operator can use this template.


##What is a requirements expression?
The one that appeared earlier

requires(T a, T b)
{
    a + b;
}

This is called a **requires expression**.

The requirements expression is,

Syntax for verifying at compile time that "such an expression can be written".

is.

This is a central function when creating a concept, and it can express a variety of conditions.

Verify that the expression exists.
This is the most basic way to use it.

template<typename T>
concept Printable =
requires(T value)
{
    std::cout << value;
};

this is

std::cout << value;

Only types that can correctly represent the expression will be accepted.

In other words, it's a type for which `operator<<` is defined.

##Check for the existence of member functions
You can also check whether a member function exists.

template<typename T>
concept HasBegin =
requires(T container)
{
    container.begin();
};

With this

std::vector

std::list

std::set

These meet the conditions.

on the other hand

int
double

These do not satisfy the condition because they do not have a begin() method.

The return value is also constrained.
Not only does the formula exist,

You can even specify the return type .

template<typename T>
concept Comparable =
requires(T a, T b)
{
    { a == b } -> std::convertible_to<bool>;
};

Here it comes

-> std::convertible_to<bool>

teeth,

"The return value of this expression must be convertible to a boolean value."

That's what it means.

Not only does the == exist,

We can guarantee that it can be used as a comparison operation.

`noexcept` guarantees that no exceptions will be thrown.
The `Requires` expression also allows us to verify that the expression does not throw an exception.

template<typename T>
concept SafeSwap =
requires(T a, T b)
{
    { a.swap(b) } noexcept;
};

this is

a.swap(b)

There exists,

Furthermore, it requires that the condition be `noexcept`.

This is a common way of writing code, often used in library implementations.

Write multiple conditions
Of course, you can specify multiple conditions simultaneously.

template<typename T>
concept Sequence =
requires(T container)
{
    container.begin();
    container.end();
    container.size();
};

If you write it like this,

begin()

end()

size()

Only types that possess all of the above satisfy the condition.

Benefits of using Concept

1. Error messages are easy to understand.

If it says so,

It's easy for people reading the code to understand, and it naturally conveys the API's design intent.

3. Easier to read than enable_if
Prior to C++17, std::enable_if was commonly used to specify template constraints.

For example, if you write a function that only accepts integer types,

template<
    typename T,
    std::enable_if_t<std::is_integral_v<T>, int> = 0>
void Print(T value);

It will look like this.

Concepts,

template<std::integral T>
void Print(T value);

That's all.

Even with the same meaning, readability has greatly improved.

summary
Concepts is a new feature in C++20 for imposing constraints on template arguments .

Traditional templates had a problem where passing an unsupported type would result in complex compilation errors within the template. By using Concepts, you can explicitly specify the types that are accepted, making the intent of the code easier to understand, as well as making error messages easier to comprehend.

Furthermore, in addition to using standard Concepts, it is also possible to express unique type requirements by defining your own Concepts.

If you have the opportunity to use templates, Concepts is one feature you should definitely take advantage of. Especially when writing new C++20 or later code, using Concepts instead of std::enable_if will allow you to write more readable and maintainable code.
